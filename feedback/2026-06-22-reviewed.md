## 2026-06-21 — faceto F-inline-add (full depth)

Roadmap feature (not a GH issue): direct on-board add gestures. Shipped on a
branch across two commits. Verdict: **"the skill is a good choice to interact
with AI."**

### Probes & attention — planted error too buried

- **The planted error (col=0) was good, but too dissolved inside the text.** §6's
  "bundle the probe with a useful instruction" worked against it here — it buried
  the claim so far that it read as prose, not as a "evaluate this" beat. → Keep the
  bundling, but sharpen the *evaluative frame* (a clearer "sanity-check this one"
  cue) so the probe tests reasoning, not reading-archaeology. (Complements
  termherd #23's note that probes already tax reading.)

### The prediction gate (§5 "guess the result")

- **Very useful for understanding** — it exposed a wrong mental model (the
  repeat-prepend marching left) the user would not otherwise have surfaced.
- **But it tipped into feeling like a "learning session"** rather than co-creation
  at times. → Watch the ratio: a prediction should feel like committing a position
  to be *attacked*, not answering a teacher's quiz. Fewer, higher-stakes
  predictions; skip the ones whose answer is obvious.

### /glance interaction

- **Activating `/glance` genuinely helped cognitive load** — but it **"dissolved
  the efforts."** The scannable tables/TL;DRs flattened the adversarial work so it
  read as lighter than it was; the tension and the effort got hidden by tidy
  formatting. → If glance is on *during* a pairing, the skill must preserve the
  adversarial beats explicitly (the attack, the defense, the pause) and not let the
  format erase the sense of work done. (Pairs with termherd #23: glance trades
  away the AI's ability to "trick" and weakens felt rigor.)

### Process legibility — the biggest miss

- **No TODO / plan view.** The 11 phases were never surfaced as a trackable plan.
  The user named the *absence* as "very important information for the process to be
  understandable" — without it they couldn't see where in the arc they were. → The
  skill should drive a **visible task list mapping the phases**, updated as each
  phase opens/closes, so position and progress are legible throughout. Treat this
  as a default, not an option.

## 2026-06-21 — termherd #23 (full depth, restart-fresh)

### Probes & attention

- **Missing the planted probe was not a problem here.** It coincided with rich
  interaction; the session had started from the user being genuinely puzzled by
  the AI's initial claim, so attention was already high.
- **The user catching a *genuine* AI error is itself a strong attention signal.**
  It may substitute for firing an error/elephant probe — or may not. **Decide
  after a few sessions**, don't change the mechanic yet.
- **Probes make the user read in a slightly paranoid mode.** Good for attention,
  but tiring. Compensate with easier-to-read statements elsewhere so the budget
  isn't spent fighting prose density.

### Session length

Longer than a usual session. Causes, in order of concern:

1. **Interruptions** — only a small increase. Not a problem.
2. **AI mistakes** — wrong claims about app behaviour at least twice; and a
   stretch where the new buttons couldn't be verified in the running app.
   (Factual cause of the latter: the installed app held the single-instance
   lock, so the user kept seeing the old build — the process critique is that
   the AI should check for a running instance *before* asking the user to run.)
3. **Too much text** — see below.

### Readability / tone

- **Long sentences and paragraphs tax concentration.** `/glance` would help but
  loses information and weakens the AI's ability to "trick" via errors/elephants.
  So the fix is **tone adjustment over sessions, not a blunt mode switch.**
- **Mostly prose, few interactive multiple-choice questions.** More prose = more
  cognitive load and harder to focus. **Lean more on AskUserQuestion-style
  structured questions** where a decision is being made.
- Reserve dense prose for where it genuinely matters.

### Interaction mechanics

- **"Async mode: D" is not understandable.** The bare letter `D` has no meaning
  to a new user and is confusing. **Remove it** (or replace with plain words —
  "I'll pause here until you answer").
- **Add a visual marker when user interaction is required** — an emoji or a
  formatted intro line, so the "your turn" moment is unmissable.
- **Parallel responses worked nicely once**, but the other times weren't truly
  parallel with the AI's processing. Worth making the parallelism reliable.

### Open questions to revisit

- Does a user's genuine-error correction replace a planted probe? (TBD, multi-
  session.)
- What's the right prose-vs-structured-question balance?
